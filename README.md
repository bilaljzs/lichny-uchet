# Личный учёт — finance tracker

React-фронтенд (тот же дизайн и функционал: Обзор / Люди / Расчёт / Итоги) с
настоящим бэкендом на Node.js/Express + PostgreSQL вместо браузерного хранилища.

## Архитектура

- `server/` — Express API. Пароли хешируются через bcrypt, сессии — через JWT.
  Данные хранятся в PostgreSQL (например, бесплатная база на Supabase); каждая
  запись помечена `user_id`, и **каждый запрос к базе жёстко фильтруется по
  `user_id` залогиненного пользователя** — один логин никогда не видит и не
  может изменить данные другого, даже если оба хранятся в одной базе.
  В продакшене этот же сервис отдаёт и собранный фронтенд (`client/dist`),
  поэтому весь сайт — это один процесс/один деплой.
- `client/` — React (Vite) фронтенд, 1-в-1 повторяющий исходный дизайн/UI.
  Вместо `window.storage` используется REST API бэкенда, поэтому данные
  сохраняются на сервере и доступны с любого устройства по логину/паролю.

## Запуск локально

Нужен PostgreSQL (локально или бесплатный проект на [Supabase](https://supabase.com)).

### 1. Бэкенд

```bash
cd server
npm install
cp .env.example .env
# впишите в .env свою строку подключения к Postgres (DATABASE_URL) и смените JWT_SECRET
npm start               # слушает на http://localhost:4000
```

### 2. Фронтенд (режим разработки)

```bash
cd client
npm install
npm run dev             # http://localhost:5173, проксирует /api на бэкенд
```

## Как это работает

- Первый вход с любым логином и паролем автоматически регистрирует новый аккаунт
  (пароль сохраняется как bcrypt-хеш).
- Повторный вход с тем же логином требует правильный пароль.
- После входа фронтенд получает токен (JWT) и загружает данные аккаунта
  (`GET /api/state`), все последующие изменения сохраняются на сервер с задержкой
  0.5с (`PUT /api/state`).
- Токен хранится в `localStorage`, поэтому обновление страницы не разлогинивает —
  но данные всегда общие и одинаковые с любого устройства, так как источник
  правды — сервер.

## Деплой в интернет (бесплатно, без карты): Supabase + Render

Понадобится постоянная база данных (чтобы данные не пропадали) и хостинг для
самого приложения. Ниже — вариант без привязки карты.

### Шаг 1 — создать бесплатную базу данных на Supabase

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → войдите через GitHub.
2. **New project** → впишите любое имя, придумайте пароль базы данных (сохраните его) → выберите ближайший регион → **Create new project** (создаётся 1–2 минуты).
3. Когда проект готов: **Project Settings** (шестерёнка внизу слева) → **Database**.
4. В разделе **Connection string** выберите вкладку **URI** и скопируйте строку — она выглядит так:
   `postgresql://postgres:[YOUR-PASSWORD]@db.xxxxxxx.supabase.co:5432/postgres`
5. Замените `[YOUR-PASSWORD]` на пароль из шага 2. Это и есть значение `DATABASE_URL` — сохраните его, понадобится на шаге 2.

### Шаг 2 — задеплоить приложение на Render

1. Зайдите на [render.com](https://render.com) → зарегистрируйтесь через GitHub (карта не нужна).
2. **New** → **Blueprint** → выберите репозиторий `bilaljzs/lichny-uchet` (если Render его не видит — нажмите **Configure account** и дайте доступ к репозиторию).
3. Render найдёт файл `render.yaml` в корне репозитория и предложит создать сервис `lichny-uchet` — нажмите **Apply**.
4. Откроется страница сервиса → вкладка **Environment** → найдите переменную `DATABASE_URL` и вставьте туда строку из шага 1. `JWT_SECRET` Render сгенерирует сам.
5. Сохраните — начнётся деплой (сборка фронтенда + запуск сервера, 2–5 минут).
6. Когда статус станет **Live**, наверху страницы будет ссылка вида
   `https://lichny-uchet.onrender.com` — это и есть готовое приложение,
   доступное с любого устройства.

Примечание: на бесплатном плане Render сервис «засыпает» после ~15 минут без
запросов и следующий заход занимает ~30–50 секунд на «пробуждение» — это
не влияет на сохранность данных (они в Supabase), только на скорость первого
открытия.
