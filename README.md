# Личный учёт — finance tracker

React-фронтенд (тот же дизайн и функционал: Обзор / Люди / Расчёт / Итоги) с
настоящим бэкендом на Node.js/Express + SQLite вместо браузерного хранилища.

## Архитектура

- `server/` — Express API. Пароли хешируются через bcrypt, сессии — через JWT.
  **У каждого логина — своя собственная физическая база данных**
  (отдельный файл SQLite в `server/data/users/<id>.db`), поэтому данные разных
  пользователей полностью изолированы друг от друга на уровне файловой системы.
  Учётные данные (логин + хеш пароля) хранятся отдельно, в общей `server/data/main.db`.
- `client/` — React (Vite) фронтенд, 1-в-1 повторяющий исходный дизайн/UI.
  Вместо `window.storage` теперь используется REST API бэкенда, поэтому данные
  сохраняются на сервере и доступны с любого устройства по логину/паролю.

## Запуск локально

### 1. Бэкенд

```bash
cd server
npm install
cp .env.example .env   # при желании поменяйте JWT_SECRET
npm start               # слушает на http://localhost:4000
```

### 2. Фронтенд

```bash
cd client
npm install
npm run dev             # http://localhost:5173, проксирует /api на бэкенд
```

Для продакшен-сборки фронтенда: `npm run build` в `client/`, раздать `client/dist`
любым статик-сервером; либо задать `VITE_API_URL` на адрес бэкенда перед сборкой,
если фронтенд и бэкенд не на одном домене.

## Как это работает

- Первый вход с любым логином и паролем автоматически регистрирует новый аккаунт
  (пароль сохраняется как bcrypt-хеш).
- Повторный вход с тем же логином требует правильный пароль.
- После входа фронтенд получает токен (JWT) и загружает данные аккаунта
  (`GET /api/state`), все последующие изменения сохраняются на сервер с задержкой
  0.5с (`PUT /api/state`) — как и в исходном приложении с автосохранением, только
  теперь в реальную базу данных, а не в браузер.
- Токен хранится в `localStorage`, поэтому обновление страницы не разлогинивает —
  но данные всегда общие и одинаковые с любого устройства, так как источник
  правды — сервер.
